# 지침 16. 충돌 — 실측에서 출발하는 브로드페이즈

> 선행: [지침 10](10-core-array.md), [11](11-kernels.md), [13](13-events-and-units.md)

## 우리가 이미 아는 것 (highspeed/ 실측)

반벡터화 O(N²) — 개체 i마다 `pos[:, i+1:]`와의 거리 제곱을 벡터 연산:

| N | 시간 |
|---|---|
| 500 | ≈10ms |
| 1000 | ≈28ms |
| 900~1300, (N,3) 세로 배열 | ≈60ms (속성-메이저의 2배) |

결론: **N ≤ 500 상호 충돌은 브로드페이즈 없이도 예산 안이다.** 그 이상, 그리고 "총알 10k vs 병사 1k" 같은 비대칭 충돌은 구조가 필요하다.

## 3단 전략 — 필요해질 때까지 다음 단으로 가지 않는다

### 1단: 반벡터화 O(N²) (지금 있는 것의 정리)

소규모 아키타입 간/내 충돌용. 커널로 정식화:

```python
def collide_brute(pos_a, rad_a, pos_b, rad_b) -> (idx_a, idx_b):
    """A×B 전수. 반환은 겹친 쌍의 int64 인덱스 두 배열."""
```

### 2단: 균일 그리드 해시 브로드페이즈 (기본 채택안)

세계를 셀 크기 `cell`(최대 반지름×2 권장)로 나눠, 같은/이웃 셀 안에서만 좁힌다. numpy만으로:

```python
cid  = (pos // cell).astype(np.int64)              # (3,N) 셀 좌표
key  = (cid[0]*73856093) ^ (cid[1]*19349663) ^ (cid[2]*83492791)   # 해시 (또는 좁은 월드면 선형 인덱스)
order = np.argsort(key)                             # 셀별로 모으기
# 정렬된 key의 경계(np.diff != 0)로 셀 구간을 얻고, 구간별 brute 커널 호출
```

- 전부 벡터 연산이고, 셀 구간 루프는 "점유 셀 수"에 비례한다 (N이 아니라).
- 비대칭 충돌(총알→병사)은 병사만 그리드에 넣고 총알 셀 좌표로 조회 — 더 싸다.
- argsort는 O(N log N)이지만 numpy C 구현이라 N=10만에서 ms급. 재라.

### 3단: Numba 승격 ([지침 17](17-profiling-and-numba.md))

그리드로도 예산을 넘으면 — 이것이 **Numba 1호 승격 대상**이다 (D-012의 예정지).
셀 구간 이중 루프는 벡터화보다 njit 루프가 자연스럽고 임시 배열이 없다. 시그니처는 2단과 동일하게 유지.

## 충돌 결과의 배달 (제4·5조 준수)

커널 출력은 `(idx_a, idx_b)` 인덱스 쌍 — 이벤트 객체가 아니다.

- **집계 반응** (총알 데미지, 소멸): 그대로 커널로 —
  `hp[idx_b] -= dmg[idx_a]`, `alive[idx_a] = False`. N-스케일을 2층에 올리지 않는다.
- **개성 반응** (보스 피격 연출, 업적): idx를 uid로 바꿔 2층 이벤트로 배달 — 프레임당 소수만.
- 판별: "이 반응이 쌍마다 다른 코드를 요구하는가?" 아니오 → 1층. 예 → 2층.

같은 인덱스가 한 프레임에 여러 쌍에 등장할 수 있다 — `hp[idx] -= d`는 중복 인덱스에서 마지막 것만 반영된다(numpy fancy 대입 규칙). 합산이 필요하면 `np.subtract.at(hp, idx, d)` (느림 — Numba 승격 사유가 되기도 한다).

## 함정

- 셀 크기 < 최대 반지름×2면 이웃 셀 검사가 3³=27셀을 넘어야 한다 — 반지름 상한을 아키타입 스키마에 명시.
- 음수 좌표의 `//`는 파이썬/넘파이 floor라 안전하지만, `astype(int)` 절단과 섞으면 경계 셀 버그. floor 나눗셈으로 통일.
- 겹침 판정은 거리 제곱 vs 반지름 합 제곱 — sqrt 금지 (mag2 습관, vector.py에서 이미 확립).
