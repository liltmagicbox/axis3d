# Kickoff (2026-09-18)

## Asked
The user asked, in Korean, for a system of many markdown documents so that sub-models each play a role
(rule checking, implementation, error/edge-case collection, performance evaluation, style, records, "and so on;
don't be too bound by what I said, aim for better judgement"). Documents must be short by current standards,
in English to save tokens, with Korean briefs. The engine: Python 3D simulation with uv, PyOpenGL, glfw, numpy;
compute shaders, collision physics, data-oriented ECS, state snapshots, state transfer over the network,
"effectively a game engine", glTF scene export, later a Godot port; GL-based but Vulkan-ready for ray tracing;
an abstract graphics-card interface with minimal state; "elegant" SSBO use; depth 0–1; desktop GL 4.6; DSA and AZDO;
educational code that impresses a curious reader and that a beginner can follow, with deliberately isolated hard parts.

Direct quotes that shaped decisions:
- "Yup? Zup? GL기반이니 그걸 지향하되 필요한 시점에 분리할 필요도 있을 듯. 시뮬레이션이니 수학 교육 관점에서 zup 이 나으려나" → ADR 0005.
- "복잡한 구조로 빠져들거나 api가 폭증하거나 안 해야 함" → ADR 0019, `rules/simplicity.md`.
- "Ai가 결정해야하는 것들은 판단 하에 저장해서, 이후 내가 보고 숨겨진 가정이나 편향을 발견하면 좋음" → `records/assumptions.md`, ADR "Assumptions (check me)".
- "가령 해당 api를 호환하는 OpenGL es 3.1용의 소형 미니 엔진을 만들어야 할 수도 있다" → `variants/gles31.md`, `packs/port_gles31.md`.
- "코드 작성이나 테스트 같은 것은 소형 모델도 처리 가능했으면" → task cards with literal signatures and test names; model sizes per role.

## Options raised
- Host: new repo / `new3dkatsu` / `axis3d` → `axis3d` (ADR 0001).
- Up axis: Y-up everywhere / configurable / Z-up with one conversion → Z-up (ADR 0005).
- ECS storage: the user's `(k, N)` `Axis` table / sparse sets / archetypes / dense per-table columns → dense columns (ADR 0004).
- Doc structure: one big CLAUDE.md / skills only / layered roles-rules-spec-variants-decisions-packs-tasks-records → layered (ADR 0021).

## Outcome
Decisions 0001–0026 written; specs, rules, variants, packs, templates, ledgers, tools and a 23-card first sprint created.
The user has not yet confirmed any of the AI-made choices; every one is a row in `docs/records/assumptions.md`.

## Open questions

- 4 spaces vs tabs (A-005), English-only code (A-013) → user.
- Move legacy root files to `legacy/` (task 0020) → user.
- Is a CI workflow wanted (A-020)? → user.
- Priority of the GLES 3.1 mini engine relative to the first rendered frame → user.

## Disagreements (one line per side)
- The user measured `(3, N)` faster than `(N, 3)` (B-002) / the ADR keeps `(N, 3)` because the measured pattern (a per-row loop) is banned; to be re-measured (A-015).
