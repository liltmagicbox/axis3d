# 02. AI와 일하는 방식

이 프로젝트는 사람(설계 결정)과 Claude(구현·실험·문서화)가 세션 단위로 협업한다.
전제: **문서가 곧 기억이다.** 세션은 휘발되지만 docs/는 남는다. 대화에서 결정된 것이 문서에 없으면 결정되지 않은 것이다.

## 세션 리추얼

**시작할 때** (Claude가 스스로 할 일):
1. `CLAUDE.md` → `docs/STATUS.md` → 이번 주제의 `docs/guides/XX-*.md`를 읽는다.
2. STATUS의 "다음 할 일"과 사용자의 요청이 어긋나면 짚고 시작한다.

**끝낼 때**:
1. 돌아가는 상태로 커밋한다 (깨진 채로 세션을 넘기지 않는다).
2. `STATUS.md` 갱신: 한 일 / 다음 할 일 / 막힌 것.
3. 설계가 바뀌었으면 해당 가이드 문서와 `decisions.md`를 같이 고친다.

## 세션의 크기

- **한 세션 = 한 주제.** "guides/10의 3~5단계"처럼 가이드의 단계 묶음이 이상적 단위다.
- 좋은 요청 예: `docs/guides/13 읽고 2단계 진행해줘`, `guides/16 완료 기준까지 끌고 가줘`.
- 주제를 벗어난 발견(버그, 아이디어)은 그 자리에서 고치지 말고 `ideas.md`나 STATUS의 막힌 것에 적는다.

## 역할 분담

| | 사람 | Claude |
|---|---|---|
| 설계 방향, 취향, 우선순위 | 결정 | 선택지와 트레이드오프 제시 |
| 구현, 보일러플레이트, 테스트 | 검수 | 작성 |
| 벤치마크 | 어떤 질문을 잴지 | 실험 코드 작성·실행·수치 기록 |
| 문서 | 승인 | 갱신 유지 |

원칙: **설계 방침(01)과 어긋나는 코드를 쓰게 되면 Claude는 멈추고 물어본다.** 조용히 방침을 우회하지 않는다.

## 검증 의무

- "될 것 같다"는 보고 금지. 커널 하나를 만들면 데모 실행 결과를, 성능 주장을 하면 측정 수치를 함께 낸다.
- 모든 모듈의 `__main__` 데모가 세션 종료 시점에 전부 돌아야 한다 (제10조).
- 성능 수치는 실험 파일 안에 주석으로 박제한다 — 기존 `test_np*.py`들이 그 전통이다.

## 탐색 코드의 자리

기존 저장소의 미덕은 왕성한 사고실험(`_concept_*.py`, `test_*.py`, 주석 독백)이었다. 계승하되 자리를 준다:

```
project/
  core/          # 1층: 배열, 커널 — 깨끗하게 유지
  world/         # 2층: unit, behavior, events
  view/          # 경계 바깥: renderer, window, web
  experiments/   # 벤치마크·사고실험. 지저분해도 됨. 결론은 주석으로 박제
  docs/          # 이 문서들
```

experiments/는 리팩터링·린트 대상이 아니다. 대신 파일 맨 위에 한 줄 요약과 날짜, 맨 아래에 결론을 남긴다.

## 커밋

- 작동 단위로 자주. 메시지는 `영역: 무엇을 왜` 한 줄이면 충분 (기존의 `** mesh_dict !` 스타일보다 미래의 자신에게 친절하게).
- 실험 결과 커밋은 결론을 메시지에 담는다: `experiments: (3,N) beats (N,3) 2x on collision loop`.

## 새 프로젝트용 CLAUDE.md 씨앗

새 저장소를 팔 때 아래를 복사해 시작한다 (이 저장소의 CLAUDE.md에서 상태 설명만 뺀 것):

```markdown
# CLAUDE.md

파이썬 3D 시뮬레이션. 설계 문서는 docs/에 있고, 그것이 이 저장소의 헌법이다.

## 매 세션
1. docs/STATUS.md 읽고 시작, 끝나면 갱신.
2. 작업 주제의 docs/guides/XX 문서를 따른다. 방침과 충돌하면 묻는다.
3. 세션 끝 = 돌아가는 상태 + 커밋 + STATUS 갱신.

## 규칙 요약 (전문: docs/01-design-principles.md)
- 상태는 속성-메이저 (dims,N) float32 배열, 인덱스는 int64 (np.nonzero 반환 그대로).
- 핫패스에 파이썬 객체·루프 금지. 커널은 배열+스칼라만 받는 순수 함수 (Numba 대비).
- 고급 로직(이벤트/Behavior/컨트롤러)은 2층 — 배열 밖. 인덱스로만 1층을 만진다.
- GPU 계산 금지, 그리기 전용. 시뮬은 headless로 돌 수 있어야 한다.
- 모든 모듈에 __main__ 데모. import 부수효과 금지.
- 성능 주장에는 측정 수치. 실험은 experiments/에, 결론은 주석+docs/decisions.md에.

## 레이아웃
core/ (1층) · world/ (2층) · view/ (경계 밖) · experiments/ · docs/
```
