# 01. 설계 방침 10조

mvc3d/axis3d에서 몸으로 배운 것을 규칙으로 편 것이다. 근거는 [00-history-and-lessons.md](00-history-and-lessons.md).
어기고 싶어지면 어기기 전에 [decisions.md](decisions.md)에 기록한다.

## 제1조 — 시뮬레이션이 유일한 진실이다

World(시뮬레이션)는 뷰 없이 완결적으로 돈다. 뷰·입력장치·네트워크는 전부 교체 가능한 손님이다.
경계 인터페이스는 좁게 유지한다: world는 `input(event)` / `update(dt)` / `draw()` 셋, 뷰는 `get_inputs()` / `draw(draws)` 둘.
이 다섯 개를 넘는 구멍을 뚫지 않는다.

## 제2조 — 상태는 속성-메이저 배열에 눕힌다 (ECS 아님)

개체는 객체가 아니라 **아키타입 배열의 열 인덱스**다. 속성별 배열 `(dims, N)`, float32.
파이썬에서 정통 ECS(엔티티-컴포넌트 조회, 시스템 쿼리)는 조회 오버헤드를 감당 못 한다.
우리 구조는 조회가 없다 — 속성 접근이 곧 배열이고, "쿼리"는 불리언 마스크다. 상세: [guides/10](guides/10-core-array.md).

## 제3조 — 뜨거운 길에는 파이썬 객체가 없다

매 프레임 N에 비례해 도는 코드에서 개체 단위 파이썬 루프·객체 생성·속성 접근 금지.
커널은 배열과 스칼라만 받는 순수 함수로 쓴다. 이 형태가 그대로 Numba 확장 경로다. 상세: [guides/11](guides/11-kernels.md).

## 제4조 — 고급 객체는 2층에 산다

Unit 파사드, Behavior, Timer, Controller, GameMode, 이벤트 핸들러는 배열 밖 객체 세계(2층)에 둔다.
2층은 느려도 된다 — 프레임당 수십 건이지 N건이 아니다. 2층이 1층(배열)을 만질 때는 인덱스와 마스크로 만진다. 상세: [guides/13](guides/13-events-and-units.md).

## 제5조 — 이벤트는 경계를 못 넘는다

소켓 위로는 압축된 dict/바이트만, 시뮬 안에서는 타입 있는 Event만. 변환은 경계에서 정확히 한 번.
가해자는 대상의 상태를 직접 만지지 않고 이벤트를 배달하며, **결과는 받는 쪽이 결정한다.**

## 제6조 — GPU는 그리기 전용이다

시뮬레이션 계산을 GPU로 보내지 않는다. 근거와 예외 조건(순수 시각 효과, N 수백만+판독 없음)은 [guides/12](guides/12-cpu-vs-gpu.md).
같은 이유로 시뮬 코드는 headless로 돌 수 있어야 한다 — 서버에서 돌리는 게 기본 시나리오다.

## 제7조 — 머티리얼은 없다, draw-type이 있다

뷰에 보내는 것은 의미 있는 상태(위치·회전·본·색 인덱스)지 정점이 아니다.
렌더러는 draw-type(필요 attr 목록이 정해진 그리기 방식) 테이블로 그리고, 같은 지오메트리 N개는 instanced draw 한 방이다. 상세: [guides/15](guides/15-rendering.md).

## 제8조 — 감으로 정하지 않는다, 재고 정한다

레이아웃·인덱싱·직렬화 같은 결정은 마이크로벤치마크로 정한 전례를 따른다(00 문서의 숫자 표).
새 결정도 같은 방식으로: 실험 파일을 만들고, 숫자를 파일 안에 주석으로 남기고, 결론을 decisions.md에 적는다. 상세: [guides/17](guides/17-profiling-and-numba.md).

## 제9조 — 증설은 상각, 할당은 free-list, 삭제는 마스크

배열은 50% 단위로 늘리고, 빈 슬롯은 free-list로 재활용하고, 죽은 개체는 active 마스크를 끈다.
생성은 배치(`acquire(n)`)가 기본 — 낱개 append 루프는 10배 느리다는 게 실측이다.

## 제10조 — 모든 모듈은 즉시 실행 가능하다

모든 모듈에 `if __name__ == '__main__':` 데모/테스트를 유지한다 (기존 습관 계승).
"돌려보면 아는" 상태를 유지하는 것이 문서보다 강한 회귀 방지책이다. 단, 이제는 import 시 부수효과가 없게 — 실행 코드는 반드시 main 가드 안에.
