# 03. 스케줄 관리

커밋 기록이 말해주는 현실: 이 프로젝트는 **버스트로 진행된다** (2022년 8~10월, 2023년 8~9월처럼 몰아서 하고, 길게 쉰다).
일정 관리는 그 현실을 부정하지 말고 설계에 반영한다.

## 세 가지 규칙

1. **언제든 끊겨도 되게.** 모든 세션은 돌아가는 상태 + STATUS.md 갱신으로 끝난다.
   반 년 뒤에 돌아와도 STATUS 한 페이지 → 해당 가이드 문서 순서로 읽으면 이어서 할 수 있어야 한다.
   (mvc3d에 2025년 1월에 돌아왔을 때 "vrbutton_whatis_this" 커밋이 남았다 — 다시는 그러지 않기 위한 규칙이다.)
2. **마일스톤은 데모로 정의한다.** "충돌 시스템 구현" 같은 상태가 아니라 "총알 1000발이 병사 무리에 맞아 사라지는 데모가 돈다"처럼 실행해서 보여줄 수 있는 것으로.
3. **주차장을 쓴다.** 아이디어가 넘치는 것이 이 프로젝트의 엔진이자 브레이크였다 (주석 독백들이 증거).
   떠오른 것은 [ideas.md](ideas.md)에 한 줄 적고 하던 마일스톤으로 돌아온다. 버스트가 시작될 때 주차장에서 골라 꺼낸다.

## 버스트 운영법

- **버스트 첫 세션**: STATUS 읽기 → 마일스톤 하나 고르기 → 가이드의 단계를 세션 크기로 쪼개기.
- **버스트 중**: 하루의 끝 = 커밋 + STATUS 세 줄 (한 일 / 다음 것 / 막힌 것).
- **버스트 끝** (며칠 손 놓게 될 것 같으면): STATUS에 "복귀 지점" 절을 한 단락으로 — 지금 어디까지 왔고, 돌아오면 뭘 실행해서 상태를 확인하면 되는지.
- **복귀**: 복귀 지점 단락 → 데모 실행 → 이어서. 코드를 읽으며 상태를 역추적하는 일을 없애는 게 목표다.

## 시간 감각

- 한 세션은 마일스톤의 1/3 ~ 1/2를 넘보지 않는다. 데모가 커지면 마일스톤을 쪼갠다.
- "2주 연속 같은 마일스톤에 막혀 있다"가 감지되면 범위를 줄이는 결정을 decisions.md에 적고 진행한다. 완벽한 M2보다 도는 M4가 가치 있다 — 경계가 뚫려야 눈으로 보면서 만들 수 있다.
